## Day 31 Agent 异常处理与熔断

- **实现机制**：
  - 同一工具连续失败 2 次 → 熔断禁用
  - 总步数上限 10 步 → 强制终止
  - 每步执行日志记录
- **测试场景**：调用损坏的计算器（`broken_calculator`，直接抛出 RuntimeError）
- **测试结果**：Agent 调用 1 次后发现工具返回“内部错误”，判断重试无意义，转而用自己的知识给出正确答案（56,088）
- **发现的问题**：错误信息太明确时，模型会选择不重试。需要模拟“超时”等可重试的临时故障才能完整验证熔断逻辑
- **改进方向**：增加间歇性故障工具，让 Agent 有理由重试，从而触发完整的“失败计数 → 熔断”流程
- **关键收获**：熔断机制的设计需要结合实际故障类型，临时故障应给出“请重试”提示，永久故障应给出明确错误信息
